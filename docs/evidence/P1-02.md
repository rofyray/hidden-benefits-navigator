# P1-02 — Run the device and provider preflight

Status: complete
Date: 2026-09-19

## Changed

- `src/client/adapters/capabilities.ts` — independent probes for the on-device
  language model, local speech pack, microphone permission and local playback
  voice, plus `selectCapabilityPlan()` (voice / typed-local / manual).
- `src/routes/preflight.tsx` — capability probe page: per-capability state and
  plain-language detail, re-run control, user-triggered model download with a
  progress monitor, explicit microphone request, selected plan, and a manual
  button for the synthetic provider check.
- `src/server/jev/client.ts` — server-only transport: pinned `jev-1.13.0`,
  8 s total budget, 3 attempts, retry only on 408/429/5xx, `Retry-After` and
  `retry-after-ms` respected, 512 KB response cap, no upstream body retained.
- `src/lib/preflight.functions.ts` — `probeJev` server function; returns
  `{configured, ok, model, code, durationMs}` only. Never returns the key,
  payload or provider body.
- `tests/unit/capabilities.test.ts`, `tests/unit/jev-client.test.ts`.
- `docs/decisions/device-preflight.md`.

## Acceptance evidence

- Each capability has a measured result → Playwright run against
  `http://localhost:8080/preflight` (HeadlessChrome 141.0.7390.37, Linux x86_64,
  fresh profile) → on-device model: `not supported here`; local speech pack:
  `Ready`; microphone permission: `not decided`; local playback voice:
  `not known (no voices registered)`; console errors: none.
- Capability plan selected → same run → "manual" plan shown: "You will answer a
  short set of questions on a form." Manual mode depends on no browser AI
  capability and is runnable.
- One tiny synthetic Jev request from the server → `bun /tmp/jevprobe.ts`
  (synthetic state `{"probe":{"statement":"The sky is blue."}}`, one noul) →
  outcome `ok` in 595 ms, returned model `jev-1.13.0` = pinned model, answer
  `{"probe_ok":{"type":"noul","noul":0.99}}`. Same check through the UI button:
  "Reachable. Version reported: jev-1.13.0." No key or payload recorded.
- Mocked unavailable/downloading/denied states → `bun run test` →
  `nanoStateFromAvailability` maps available/downloadable/downloading/unavailable
  and returns `unknown` for unrecognised values; plan falls back to typed-local
  on a denied microphone and to manual on an absent or merely downloadable model.
- Transport contract → `bun run test` → missing credential yields
  `not_configured` without a network call; an unpinned `JEV_MODEL` yields
  `unevaluated_model`; 400 is not retried (1 call); 503 with `retry-after-ms`
  retries to 3 calls then fails `temporarily_unavailable`.
- Commands: `bun run typecheck` pass · `bun run lint` 0 errors (6 pre-existing
  warnings in shadcn UI files) · `bun run test` 15/15 pass across 4 files.

## Data / model versions

- Jev model: `jev-1.13.0` (pinned in code; provider echoed the same value).
- Catalog / question / policy versions: not authored yet (P1-03 onward).

## Limitations

- The browser results are measured in a headless sandbox Chromium, not on a
  target Chrome profile with the on-device model enabled. No release claim of
  working voice or on-device understanding is supported by this run; a
  real-device probe is required and is carried to the P1-17 and P3-14 gates.
- The Jev credential in use was shared in chat; it must be rotated before
  public deployment.
- Cloud text understanding remains disabled and unclaimed.
