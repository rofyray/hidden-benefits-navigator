# P2-04 — One-question clarification

Date: 2026-09-19

## What was built

A follow-up layer that asks one short, authored question at a time for facts the
code found missing, and stops after three optional turns.

- `src/client/clarify/questions.ts` — the authored question bank
  (`CLARIFY_QUESTION_VERSION` `1.0.0`, `MAX_CLARIFY_TURNS` 3,
  `MAX_CANDIDATES_PER_TURN` 3). Each question carries a stable id, one contract
  field path, plain wording, and button options taken from the review
  descriptors. Two questions may share one field (`income` amount and
  `income.basis`); the basis question writes into the existing amount instead of
  replacing it. The bank order is the asking order: state, household size,
  income, food household, age, Medicare Part A, then the programme fields for the
  groups in play. The model never authors or selects a question.
- `src/client/clarify/select.ts` — pure selection over the reviewed facts. A
  question is a candidate only when its field is still an explicit unknown
  (`null`, `"unknown"`, `""`) or the extractor flagged it ambiguous, and
  programme questions are only considered for the groups this run needs.
  Resolved and skipped ids are excluded.
- `src/client/clarify/session.ts` — the turn loop. One question on screen at a
  time; `answerCurrent` handles typed values, button values, "Not sure", "Skip"
  and "Show the options". Skipping records a skip and no value. "Not sure"
  records the explicit unknown for that field shape — `"unknown"` for a yes/no
  field, nothing for a nullable one — never a "no" and never a zero. An answer
  the contracts refuse keeps the previous fact, keeps the same question on
  screen, and does not spend a turn. `needsReevaluation` is set only when an
  answer actually changed a fact, so a skip or a repeated answer triggers no
  re-screening.
- `src/routes/review.tsx` — a follow-up section on the development review
  screen: start button, one question, answer buttons or a number entry, "Not
  sure", "Skip this", "Stop the questions", a "Question N of up to 3" counter and
  a closing line. The review state moved from `useReducer` to `useState` plus the
  same `reviewReducer`, so one action can update facts and session together.
- `tests/unit/clarify.test.ts` — 26 labeled tests.

## Acceptance

- One question at a time: the session holds a single `currentId`, and the
  browser check confirms one question per step.
- Skipping never becomes a false answer: the skip path does not touch the facts
  (`revision` unchanged) and is covered by tests.
- No loop: every asked question id lands in `resolved` or `skipped` and is
  excluded from later selection; a ten-skip run visits ten distinct questions and
  ends.
- Turn cap: three completed turns close the session and `nextQuestion` returns
  `null`.
- Confirmed facts are preserved: a follow-up answer writes only to its own field.

## Limitations

- Answers are typed or chosen by button only; speech input is Phase 3.
- The question bank is English; the Spanish wording is due with P3-14.
- The "show the options" step only appears for lists longer than four options;
  shorter lists show their buttons immediately.
- Re-screening is signalled by `needsReevaluation`, not yet performed — the
  evaluation client arrives with P2-05.
- The review screen remains a development surface; visual design is Phase 3.
