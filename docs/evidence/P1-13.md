# P1-13 — Labels, ranking and clarification selection

Date: 2026-09-19

## What was built

`src/server/jev/display.ts` (new) — the central, versioned display policy
(`POLICY_VERSION` re-exported from `policy.ts`, currently `1.0.0`). Every
threshold lives in one `DISPLAY_POLICY` object: `likelyMinScore 1.7`,
`likelyMinConfidence 0.8`, `lowConfidence 0.5`, `contradictionMaxScore 1.0`,
`maxFollowUpTurns 3`, `maxFollowUpsPerTurn 3`. They are conservative engineering
starting points, not calibrated eligibility probabilities, and are still to be
validated against the labeled cases before release.

### `labelFor()` — rule evidence before model signal

The order is fixed:

1. A definitive applicable exclusion (any criterion `fail`, exception paths
   already resolved by the screening engine) → **Not a clear match**, reason
   `policy.rule_exclusion`.
2. Coverage and evidence blockers — unsupported jurisdiction / out of force
   (`policy.not_covered`), stale or unverified source (`policy.stale_evidence`),
   a blocking unknown the catalog marks material (`policy.material_fact_missing`),
   any other unknown (`policy.unresolved_criterion`) → **Possibly**. No model
   score can override this step.
3. Rules mode (`model: null`) — complete positive predicates give **Likely**
   (`policy.rule_check_complete`, `rulesOnly: true` for the fallback badge);
   unknowns give **Possibly**; exclusions gave **Not a clear match** at step 1.
4. Model signal, read only on clean rules — confidence below 0.50 →
   **Not a clear match** with `policy.low_confidence_review` (factual
   uncertainty, never a categorical denial); score at or below 1.0 against clean
   rules → **Not a clear match** with `policy.signal_conflict`; score ≥1.70 and
   confidence ≥0.80 with positive evidence → **Likely**
   (`policy.preliminary_match`); everything else → **Possibly**
   (`policy.confirm_a_detail`).

### `rankResults()`

Sorts Likely → Possibly → Other; within a label by confirmed need relevance
descending, then match score descending, then stable catalog index. A null
relevance or score sorts below any known value (as `-1`) but never becomes zero
income or a negative judgment, and never changes the label. Assigns `rank`.

### `selectFollowUps()`

Uses code's own missing-field list first. Ranks candidates by how many programs
each unlocks, then by burden (`fieldBurden`: 3 for amounts and resources, 2 for
age band / employment / Medicare Part A / existing Lifeline / tax year / filing
status, 1 otherwise), then by stable field order. Excludes: fields already
answered or asked, `AGENCY_ONLY_FIELD_IDS` (policy interpretations only an
agency can settle — the `*BasisConfirmed`, exception-status, special-rule and
household-definition fields), programs with relevance 0, and programs already
labeled Not a clear match, so a low-relevance program cannot drive repeated
invasive questions. Returns at most 3 fields, and nothing at all once 3 optional
turns are done — after that, partial results stand and can be edited.

`mostUncertainNoul()` breaks a remaining tie by closeness to 0.5, with the
question ID as a deterministic final tie-break.

## Acceptance

**Uncertain or incomplete criteria cannot become Likely from model confidence
alone.** Tested with a `score 2.0 / confidence 1.0` answer against a screening
carrying one blocking unknown: the result is Possibly with
`policy.material_fact_missing`. The blocker branch returns before the model is
ever read.

**Partial results always have a next action.** Every non-Likely label carries at
least one reason code, and follow-up selection returns either a bounded field
list or — at the turn cap or when only agency-only fields remain — an empty list
whose meaning is "show results as they stand", with agency-only items routed to
an agency step instead of a question.

## Honest limits

- The thresholds are uncalibrated starting points. The labeled-case evaluation
  that would justify them is P3 work; until then no number here should be
  described as a measured accuracy.
- Relevance and match scores are supplied by the caller; wiring them from a real
  evaluation is P1-14.
- Nothing here converts a score into a percentage chance of agency approval, and
  no benefit values are summed.
