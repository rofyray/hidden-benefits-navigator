# P1-03 — Define shared schemas and catalog validation

Status: complete
Date: 2026-09-19

## Changed

- `src/shared/contracts.ts` — one Zod package for common facts, all six program
  extensions, criterion results, evaluate/verify/health envelopes, error
  envelope and the application limits. Strict objects everywhere; missing is
  `null` or `'unknown'`; amounts are integer cents bounded to 1,000,000,000;
  households 1–20; expected infants 0–10.
- `src/shared/catalog-schema.ts` — source, evidence, rule, program and manifest
  schemas plus `validateCatalog()`. Rule operands are a discriminated runtime
  union (`enumIn|lte|gte|range|all|any|referral`); no operand is ever an
  evaluated string. `FIELD_IDS` is derived from the fact and extension schemas,
  so a rule cannot name a field the contract does not define.
- `src/shared/extraction-schema.ts` — JSON Schema generated from the same Zod
  contracts for on-device extraction.
- `tests/fixtures/builders.ts` — typed builders starting from a fully unknown
  baseline (`baseFacts`, `baseExtensions`, `synthSource`, `synthProgram`).
- `scripts/validate-catalog.ts` + `package.json` — `data:validate` now runs the
  real validator with an injected `EVALUATION_DATE` (defaults to today) instead
  of the not-configured stub.

## Acceptance evidence

All via `bun run test` (42 tests, 6 files, all passing):

- Invalid units → non-`USD` currency rejected; `period: 'taxYear'` without a
  `taxYear` rejected; a `taxYear` on a monthly threshold rejected.
- Unknown keys → `factsSchema` rejects an added `ssn`; the evaluate envelope
  rejects an added `ip`; every object is strict.
- Dangling references → `dangling_evidence`, `dangling_source`, `dangling_rule`,
  `dangling_checklist` raised on synthetic catalogs.
- Cyclic rules → `rule.a → rule.b → rule.a` raised as `cyclic_rule`.
- Impossible values → negative cents, non-integer cents, inverted intervals,
  amounts above the cap, household 0 and 21, `qualifyingChildrenCount: 4`,
  `expectedInfants: 11`, a malformed or non-existent date, and a non-HTTPS
  destination are all rejected.
- Stale / version-mismatched records → `review_overdue`, `expired_program`,
  `expired_source`, `unverified_source`, `not_published` and `duplicate_version`
  are reported as `unsupported` (demote to referral) or `error` as appropriate,
  judged against an injected evaluation date, never the clock inside the schema.
- Boundary and unknown fixtures → point intervals, open-ended intervals,
  household 20 and fully unknown baselines all parse.
- Extraction JSON Schema → generated property names match the contracts exactly
  and `additionalProperties` is false.
- `bun run data:validate` → exit 0; reports "checked 0 program file(s)" and
  "not encoded yet: snap, eitc, ceap, medicare_help, wic, lifeline".
- `bun run typecheck` pass · `bun run lint` 0 errors (6 pre-existing warnings in
  shadcn UI files).

## Data / model versions

- Schema version `1`. No catalog content authored yet, so no catalog version.

## Limitations

- `eitc.taxYear` is range-bounded here; the authoritative published-year enum is
  applied against the catalog in P1-05, not at the contract layer.
- The validator reports which of the six programs are not encoded yet; it
  cannot assert catalog completeness until P1-04 through P1-09 land.
