# P2-03 — Fact review and manual entry logic

## Changed paths

- `src/client/review/fields.ts` — plain-language descriptors for every reviewable contract field (common facts plus each program group), each with an explicit unknown option; `fieldsForGroups()` shows program-specific inputs only for groups that were asked.
- `src/client/review/state.ts` — `ReviewState`, `reviewReducer`, origin metadata (`extracted` / `confirmed` / `manual`), ambiguity flags, in-memory narrative and source spans, `unreviewedPaths()`, and `projectEvaluateRequest()` as the only path from review state to the network.
- `src/client/review/index.ts` — barrel.
- `src/routes/review.tsx` — functional basic review/manual form generated from the descriptors; works with no local model and no extraction result.
- `tests/unit/review-state.test.ts` — 17 labeled tests, including network-projection assertions.

## What the implementation guarantees

- **Confirmation precedes screening.** `projectEvaluateRequest` returns `not_confirmed` until the person confirms, and any later change clears `confirmed`.
- **Manual edits outrank the model.** `applyExtraction` never overwrites a field whose origin is `manual`, and a run computed for an older revision is dropped whole rather than merged.
- **Nothing is invented.** Defaults are explicit unknowns; every choice field offers "I don't know"; an edit outside the shared contract is refused and the previous value stands (`lastRejectedPath` drives the message).
- **Ambiguity is preserved.** A range the model could not pin down is flagged and shown as "Not clear yet — please check this one" until the person answers it; answering clears the flag.
- **Narrative stays local.** `narrative` and `sourceSpans` live in state only. The projection is built key by key from `evaluateRequestSchema`, so no free text, quote or offset can ride along.

## Limitations

- The screen is a development surface, not the final visual design (Phase 3 owns voice and polish).
- Source spans are stored and excluded from the projection, but the extractor does not yet produce them; the highlight UI arrives with the intake screen.
- Clarification questions for ambiguous or missing fields are P2-04; this task only marks them.
- The catalog version used by the screen's confirm action is hard-coded pending the evaluation client in P2-05.
