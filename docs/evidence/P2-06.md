# P2-06 — Compose grounded explanations and checklist drafts

## What was built

A card is drafted from an **evidence snapshot** assembled by code, never from
anything the person typed.

- `src/client/compose/snapshot.ts` — `buildSnapshot(response, programId)` /
  `buildSnapshots(response)`. The snapshot carries the program id and name, the
  label exactly as the screening result set it, up to 8 catalog evidence records
  (reason evidence first, then criterion evidence, then the value evidence), and
  the curated checklist choices: documents whose rule actually passed plus the
  program's application routes, capped at 6. Evidence is stripped to
  `{id, text, kind}` — source ids never travel. An id the catalog does not back
  is dropped rather than echoed; a result with no backed evidence at all yields
  `null`, so the card uses reviewed prose instead of asking for a draft. There is
  no field on the snapshot that could hold a narrative, source span, exact income
  or link.
- `src/client/compose/prompts.ts` — `COMPOSE_PROMPT_VERSION` `1.0.0`, the
  reviewed prompt text from the PRD verbatim, `COMPOSE_BUDGET`
  (`perProgramMs` 5000, `totalMs` 20000, `concurrency` 2) and
  `draftJsonSchema(snapshot)`, which constrains checklist ids to the curated set
  and every `evidenceIds` entry to that snapshot's own ids.
- `src/client/compose/validate.ts` — `parseDraft(raw, snapshot)`. Checks, in
  order: no identifier/URL-shaped text anywhere in the raw answer, valid JSON,
  both arrays present, item shape, contract bounds (≤3 sentences, ≤6 checklist
  items, ≤200 characters), no duplicate ids, every cited evidence id present in
  the snapshot, every checklist id inside the curated set. A draft that fails any
  check is discarded **whole** — the invalid part is precisely the ungrounded
  part, so patching it would be inventing. Empty arrays are reported as `empty`,
  the model's legitimate way of saying the evidence does not support more.
  `curatedCard(programId)` resolves the reviewed `fallbackExplanation` and
  `fallbackChecklistIds` to labels.
- `src/client/compose/generate.ts` — `composeDrafts(snapshots, factory, opts)`.
  One fresh `purpose: "explanation"` session per card, destroyed in a `finally`.
  Two cards at a time. Each card has its own deadline, enforced both by aborting
  the signal and by racing the prompt, so a session that ignores cancellation
  still cannot hold the page. The whole batch has one budget; once it is gone the
  remaining cards resolve as curated with `budgetExhausted: true`. The function
  always resolves with one card per snapshot, in order, so a caller never handles
  a gap.
- `src/client/compose/index.ts` — barrel.

## Contamination

Generation cannot see intake state by construction, not by discipline:

- the prompt is built from the snapshot alone, and the snapshot has no narrative
  field;
- every card gets a newly created session, so no turn history exists;
- the session purpose is always `explanation`, never the extraction session.

Tests assert all three, and assert that evidence text is treated as data: a
draft that follows an instruction smuggled into evidence (emitting a URL) is
rejected and the card falls back.

## Limitations

- No on-device model has produced a real draft: every generation test drives a
  synthetic session. Whether the on-device model actually honours the schema and
  the 18-word preference is unknown until a capable device runs it, and the 5 s /
  20 s budgets remain proposed numbers to tune against that device.
- The drafts are not yet displayed anywhere. Nothing may be shown or spoken until
  server verification approves it, which is P2-07's job; this task deliberately
  stops at producing and rejecting drafts.
- `checkItems` rejects a sentence over 200 characters but does not enforce the
  18-word preference — that is prompt guidance, and a short faithful sentence
  slightly over 18 words is not an unsupported claim.
- The identifier screen is the shared extraction pattern list (URLs, emails,
  phone-shaped, SSN-shaped, long digit runs). Curated catalog labels may
  legitimately mention "Social Security number" as words; only identifier-shaped
  values are blocked.
