- `tests/unit/extraction.test.ts` — new: 31 labeled tests against a scripted fake

## What this guarantees

- **Derived from the contracts.** Every schema is generated from `factsSchema` and
  the six extension schemas, so the model can never be asked for a field the
  server would reject, and a field added to the contract appears automatically.
- **Explicit unknowns everywhere.** `emptyFacts()`/`emptyExtensions()` start at
  `null` or `"unknown"` — never `0` or `false`. A group that is never asked about
  keeps those unknowns, so each program receives its fields or an honest unknown.
- **Common first, then only relevant groups.** `selectGroups()` drops a group only
  on a clear stated "no" (all four WIC categories negative; Medicare Part A "no"
  and age under 60; retired/unemployed for EITC). Unknown never counts as "no".
- **Negation preserved.** A stated negative is recorded as `"no"`, tested
  directly.
- **Ambiguity preserved.** A vague amount stays a range and is flagged
  `ambiguous`, so the person is asked instead of being told a number nobody said.
- **Identifiers rejected.** A proposal containing an email, phone-shaped or
  SSN-shaped number, a long account number or any URL is discarded whole —
  covered by five labeled cases.
- **Injection resisted.** Intake is wrapped as JSON data with an explicit
  do-not-obey rule; a schema-shaped answer carrying an extra key or an
  out-of-range value fails validation instead of being clamped, and nothing
  auto-confirms: the result is a proposal for review.
- **Bounded work.** Intake capped at 2,000 characters with truncation reported,
  proposals capped at 4,000 characters, one retry at 600 characters, then the
  guided form.
- **Manual edits win.** A field the person set is never overwritten by a later
  extraction, and only fields this run actually set are marked `extracted`.
- **Independent failures.** A failed or cancelled pass does not discard the other
  passes; cancellation is reported as cancelled, not as a model failure.

## Limitations

- The fake session proves this app's handling of proposals, not Gemini Nano's
  extraction quality. Real-device accuracy is measured by the labeled evaluation
  (P1-16 harness) and remains an open item until a device with the model is
  available.
- Worded amounts ("a couple thousand") depend on the model returning a range; the
  app can only detect and flag a range, not recover a number nobody stated.
- The identifier screen is pattern-based and English-shaped; it is a second line
  of defence behind the no-free-text contracts, not a general redactor.
- Prompt token budget is not yet measured on a device; the six-group split is the
  bounding mechanism.
