# P1-11 — Server Jev transport

Date: 2026-09-19

## What was built

`src/server/jev/config.ts` (new) holds every configuration value the transport
uses: the fixed endpoint, the pinned model `jev-1.13.0`, the 512 KiB response
cap, the 8 s total budget, 3 attempts, 2 s maximum backoff. `resolveJevConfig()`
reads `TYPESAFE_API_KEY` and `JEV_MODEL` at call time (never at module scope,
because the edge runtime injects environment per request) and returns either a
resolved config or a reason (`not_configured`, `unevaluated_model`) instead of
throwing, so a caller can choose rules mode rather than prompting anyone for a
key.

`src/server/jev/client.ts` is transport only:

- **Pinned model.** The model is read from configuration; anything other than
  `jev-1.13.0` fails as `unevaluated_model` before a request is made.
- **Closed failure codes.** `JevErrorCode` is a fixed union. No upstream body,
  header or message ever becomes part of an error, a log line or a screen.
  Non-retryable statuses map to `invalid_credentials` (401/403) or
  `invalid_request` (everything else non-retryable).
- **Bounded retries.** 408, 429 and 5xx (including 529) retry, at most three
  attempts total, inside one wall-clock budget. `retry-after-ms` is preferred,
  then `Retry-After` in seconds or as an HTTP date. When the stated wait exceeds
  the remaining budget the call fails as `timed_out` rather than retrying early.
- **Credential failures never retry.** A rejected key produces exactly one
  request, so a bad or revoked credential cannot turn into a burst of calls.
- **Response size cap.** A `content-length` above the cap cancels the body
  without buffering it; an undeclared oversized body is rejected after reading.
- **Cancellation.** An abort before or during a request yields `aborted`, and
  the per-attempt timer and abort listener are always cleaned up.
- **Fallback signals.** `fallbackSignalFor(error)` classifies any failure as
  `configuration` (operator must act, `retryLater: false`), `provider` (rules
  mode with a visible fallback badge, `retryLater: true`) or `cancelled`.

## Acceptance

**No client request can choose endpoint, key, model or arbitrary questions.**
The endpoint and model are module constants in a server-only file; the key comes
from server environment. `systemOne` takes a question map built by server code
(P1-12 owns the builder); nothing in the transport accepts a URL, header,
credential or model from its caller. The only client-influenced values are
`state` and the `questions` the server constructs.

**Failed credentials do not cause repeated retries.** Verified by test: 401 and
403 each produce exactly one `fetch` call.

**Import boundary.** `src/server/**` is blocked from client bundles by the
template's import protection, and `src/lib/preflight.functions.ts` loads the
client with a dynamic `import()` inside its handler. A search of the built
browser output (`.output/public`) for `typesafe.ai`, `TYPESAFE_API_KEY` and
`jev-1.13.0` returns no matches.

## Honest limits

- No live call was made in this task. The transport has been exercised only
  against mocked responses; the live provider reachability and version were
  confirmed separately in P1-02.
- Answer validation, question construction and display policy are not in this
  task; the transport returns `unknown` and treats it as untrusted.
- The Jev API key was shared in chat and must be rotated before public
  deployment.
